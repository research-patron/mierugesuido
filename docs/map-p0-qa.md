# P0 都道府県別地図の縮尺・選択不具合（2026-09-23）

対象は追加依頼の MAP-01〜06、A25〜A34。仕様書中の販売・計測等の別作業は含めない。本番公開、コミット、プッシュは未実施。

## 原因と再現

東京都 `/map/13/` を、全国マップの図形経由、直接表示、再読み込み、戻るの4経路で再現した。1491×1055、390×844で経路による差はなく、全域フィットが原因だった。

- 全ての離島を含む外接範囲を一つの `viewBox` に収めていた。固定22座標単位の余白も地域別フィットには大きすぎた。
- PCの立川市は約3.65×2.42 CSS px、狛江市は約1.25×1.26px。390px幅では立川市約2.46×1.64px、狛江市約0.84×0.85pxで、本州側は初期の1.5倍拡大により表示枠から外れていた。
- `panFromPointerDelta` が縦横別の倍率で移動量を換算していた。SVGの `xMidYMid meet` は単一倍率なので、余白のある縦横比でドラッグ量が合わなかった。
- 実操作で島根県の768px幅等にもクリック遮断を確認した。正しい松江市の図形に `pointerdown` が届いても、フォーカス時に情報カードが右上へ現れ、`pointerup` と `click` をカードのDIVが受け取っていた。
- Chromiumの北海道390px幅では、函館市の塗り内部・実ヒット判定済みの接触点から、ブラウザーのタップ補正により鹿部町へイベントが付け替えられた。境界の単純な外接矩形を選択判定に使う修正では解消しない。
- 地域別拡大で既存ラベルの白縁が太くなり、全域用の引出線位置が不適切になったため、現表示倍率に合わせて再配置・補正した。

## 修正

- 東京は「本州側（区部・多摩）」を初期表示とし、島しょ自治体と「都道府県全域」を選択できる。遠く離れた同一自治体の図形は、元の部分を保持した表示枠に分割する。
- 共通設定を使い、鹿児島・沖縄・長崎・新潟・島根・北海道にも地域切り替えを適用。重点対象の指定だけを根拠に、全県で旧不具合が確認済みとは扱っていない。地域名は収録済み自治体名を使い、「表示枠」は行政区域名を意味しない。
- 表示対象のパスから相対余白付きで独立にフィット。元パス、島、穴、自治体コードを保持し、全域表示への経路も残す。北海道の既存6件の非自治体地理レコードの非表示方針は変更していない。
- 地図の表示地域だけを切り替える。比較表、集計対象、事業キー、CSVのURLと内容は従来の都道府県全体のデータを使用する。
- 既存の拡大・縮小・移動・選択処理を再利用し、リセットは「表示中の地域に合わせる」に分離。モバイルの自動1.5倍拡大をなくし、画面幅変更で選択地域を勝手に変更しない。
- 接触点の `elementFromPoint` によるSVGの実ヒット判定からタップ先を確定。座標変換を別実装せず、隣接図形の当たり範囲を広げない。ドラッグ後の誤選択抑止は維持する。
- 情報カードはポインターを通す。カード内の重複した「詳細を見る」リンクを削除し、図形自体と自治体選択後の詳細リンクを残す。
- 自治体選択欄をPCでも表示し、矢印・Home・Endで地域表示と選択状態を同期。未収録自治体は理由を表示し、存在しない詳細ページを作らない。地理情報のみの表示枠にも状態を表示する。

## 検証方法・再実行

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium firefox webkit
pnpm test
pnpm lint
pnpm build
# 別ターミナルで out をローカルHTTP配信した上で実行
MAP_BASE_URL=http://127.0.0.1:3125 pnpm test:map-browser
MAP_BASE_URL=http://127.0.0.1:3125 MAP_BROWSER=firefox pnpm test:map-browser
MAP_BASE_URL=http://127.0.0.1:3125 MAP_BROWSER=webkit pnpm test:map-browser
```

Google Chromeを使う場合は `MAP_BROWSER_CHANNEL=chrome` を指定する。結果は `artifacts/map-p0`、別の出力先は `MAP_QA_OUTPUT`。`MAP_REGRESSION_ONLY=1` は東京の初期縮尺検出のみであり、実操作の完了判定には通常の全検証を使う。

図形の外接矩形中心を無条件に押さず、`isPointInFill`、`getScreenCTM`、`elementFromPoint` で内部・表示範囲・遮りを検査してから `mouse.click` / `touchscreen.tap` を送る。Chromiumの一本指ドラッグはブラウザープロトコルの実タッチ入力を使う。DOMの `dispatchEvent`、ハンドラー直接実行、forceクリックは使用しない。

東京の固定対象は八王子市（132012、17-1-000）、立川市（132021、17-1-000）、狛江市（132195、17-1-000）、新島村（133639、17-4-000）。未収録状態は千代田区で確認。図形から詳細ページの自治体名・自治体コード・事業クエリーを照合する。

画面条件は1491×1055、768×1024、390×844、360×844。重点県は1491×1055と390×844で選択、ズーム、移動、地域切替、リセットを試し、768×1024または844×390へ変更して実図形から再度詳細を開く。

## 結果・証拠

- 単体・既存回帰：54ファイル、442成功、既存1スキップ。型検査成功。
- 本番ビルド成功。1,647ルートの静的生成と公開用出力の検査成功。ローカル配信のみ。
- 静的生成物のブラウザー検証：Google Chrome 153.0.8010.53、Firefox 153.0、WebKit 26.5、macOS。各96項目成功、計288項目成功。
- 全47県：パス、地域分類、有限な座標・表示範囲、部分の保持、空白・極端な縮小を検査。390×844で3ブラウザー、1491×1055でChromiumの描画を確認。
- 重点9県：3ブラウザー×PC・スマートフォンで図形選択、ズーム、移動、リセット、島しょ部（埼玉・長野は該当なし）、リサイズ後の実選択・詳細遷移が成功。
- 東京：4経路・4画面幅、複数の本州側自治体と新島村の実操作、キーボード選択、未収録表示。24地域＋全域の切り替え中、KPI・表・CSV URL・CSVバイト列が不変。
- 追加した東京初期縮尺の回帰は、修正前コードで4画面幅すべて失敗し、修正後で成功。下限は八王子市の幅60px（スマートフォン）/150px（PC・タブレット）、立川市22px/55px。実測した改善後の寸法に余裕を持たせた検出値で、地形全体の一律面積比ではない。
- 修正後の立川市はPC約123×82px、390px幅で約29×19px。小さな図形は地図の拡大と自治体選択欄を併用できる。
- 読み込み失敗、空データ、非表示からの復帰、別タブからの復帰も検証した。
- 専用のGitleaksによる変更ファイル検査で検出なし。これはローカル変更範囲の検査であり、今後の公開前に必要なステージ済み差分・Git履歴・著者・リモート等の確認を代替しない。
