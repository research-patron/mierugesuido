# 本図の輪郭・離島一覧の修正（2026-09-23）

前回公開の `e6bc0282` に対する追加修正。添付の東京・山形の画像を基準に、角張りと人工的な隙間を修正し、離島を切り替えずに一覧できる構成へ変更した。本報告は公開前の検証記録。ユーザーは一覧のみへの最終修正を含めて本番 main への反映を承認済み。

## 原因と変更

従来の生成処理は、自治体ごとに閉じた図形を別々に間引いていた。許容差 `0.003` 度で細部が失われ、同じ共有境界でも始点や分割点により残る頂点が異なる。島を含む全域から本図を拡大すると、粗い角と境界の不一致が目立った。

同じ国土交通省N03・2023年1月1日の公的データから、共有する境界区間を一度だけ簡略化して双方へ反映する方式へ変更した。許容差は `0.00015` 度。CSSの拡張、曲線の創作、太い線での塗り潰しは行っていない。河川・港湾、東京都内に入り込む県外地形等の正当な空白は残る。

八王子市のパス頂点は47から731、あきる野市との完全に一致する共有辺は3から160へ増えた。全47県、1,761地物、34,009図形部分のコード・名称・種別・地理的範囲・部分数を照合し、不変を確認。元データ、全国地図、会計・事業データ、CSVは変更していない。

地域別ドロップダウンと全域表示を撤去し、本図の地図だけを表示する。離島は常時表示の一覧とし、市町村名から直接詳細へ進める。未収録自治体は状態を表示して自治体検索へ進み、独立した自治体ではない地理情報も欄外で明記する。最終指示に従い、離島の「地図」ボタンも撤去した。地図の自治体選択欄は主図内の自治体だけを対象とし、離島は一覧の名前から選ぶ。

一覧の分類は前回からの遠隔地域設定を使用する。例えば小笠原村の複数の表示枠を自治体として重複計上せず、一つの項目にする。主図を持つ市町村の近接島は引き続き主図の地物に含む。

## 検証

- 全回帰：55ファイル、445成功、既存1スキップ。型検査成功。
- 静的ビルド成功。1,647ルート・サイトマップ・公開用アセット検査成功。
- Chrome 153.0.8010.53：110項目成功。全47県のPC描画等の追加50項目も成功。
- Firefox 153.0：110項目成功。
- WebKit 26.5：110項目成功。3エンジン合計330項目成功。
- 東京は1491×1055、768×1024、390×844、360×844。図形からの選択、4遷移経路、一覧からの選択、キーボード、未収録状態、操作前後のKPI・表・CSVの不変を確認。
- 重点7県と埼玉・長野はPC／タッチ表示でズーム、移動、リセット、リサイズ後の実図形への操作を確認。離島一覧の自治体は一度ずつ表示され、名前から正しい自治体・事業へ直接到達する。
- 画像は東京・山形の輪郭と東京・鹿児島・沖縄の離島一覧等を実際に開いて確認した。全47県の描画検査は機械検証を含み、すべての自治体を一件ずつ手動操作したものではない。

自治体の描画用JSONの合計は約13.3MBから27.5MBへ増加。都道府県ごとに必要な1ファイルを取得し、gzip換算の最大は北海道の約943KB。細かな境界を保持するための増加であり、全国地図のペイロードは不変。

未確認：実機のiPhone／Android、Windows／Linux、配布版Safari、スクリーンリーダー。Firefox／WebKitの一本指ドラッグは未確認で、両者はタップとマウスドラッグ、Chromeは実タッチ入力によるドラッグを検証している。今回の本番公開後確認は未実施。

秘密情報検査：変更58ファイルのGitleaks検査で検出なし。追加内容の資格情報・個人メールアドレス・絶対ローカルパスの検査も検出なし。

## 再検証

`pnpm test`、`pnpm lint`、`pnpm build` の後、`out` をローカルHTTP配信し、`MAP_BASE_URL` を設定して `pnpm test:map-browser` を実行する。`MAP_BROWSER=firefox` または `webkit` で別エンジンを選ぶ。全47県のPC描画は `MAP_PHASE=render MAP_RENDER_WIDTH=1491`。

描画データを更新する場合は、既存の年度を保持し、県ごとに `pnpm exec tsx scripts/gis/build-n03-simplified.ts --prefectures=13 --municipalities-only=true --cache-dir=data/raw/gis` のように実行する。原典ZIPはGit管理外のキャッシュへ保存し、DBや会計データの生成は実行しない。
